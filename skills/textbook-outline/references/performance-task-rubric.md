# 表现性任务与评价标准（UbD 评估证据的另一半）

本文档是 textbook-outline 阶段 3 设计表现性任务的权威来源，与 [ubd-framework.md](ubd-framework.md)（阶段 2 预期结果）配套。GRASPS 与评价标准（rubric）两个工具同样源自 Wiggins & McTighe《Understanding by Design》，此处按"写教材"场景做了落地化改写。本文档属**学科无关内核**（见 [../../textbook/references/subject-profile-spec.md](../../textbook/references/subject-profile-spec.md) 第 2 节）：任何学科档案下六要素与 rubric 的写法逐条相同，下文示例取自线性代数只是举例。

## 1. 为什么任务必须配评价标准

UbD 阶段二「确定评估证据」的标准配置是三件：**表现性任务 + 评价标准 + 其他证据**。本 skill 组合的"其他证据"由例题习题计划承担得很充分（三类题 + Bloom 梯度 + 真算验证），缺口一直在中间那件。

没有评价标准的表现性任务，是一句口号：

- **作者无法评**——任务写着"给出一个降维方案并论证合理性"，什么样算论证充分？两个作者会给出两种判断；
- **学生不知道"好"长什么样**——只知道要交什么，不知道往哪个方向努力，这恰好是表现性任务本该解决的问题；
- **迁移目标失去唯一落点**——迁移目标是五件套里最高的一件（指向真正的迁移能力），它在全书唯一的检验方式就是表现性任务。任务不可评，等于迁移目标不可验，`ubd-framework.md` 第 2.4 节"必须被至少一个表现性任务覆盖，否则就是空话"这条要求就只完成了一半。

## 2. GRASPS：表现性任务的六要素

每个表现性任务用六要素写清，缺一要素就会退化成一道大号习题：

| 要素 | 问什么 | 关键约束 |
| ------ | -------- | ---------- |
| **G**oal 目标 | 要达成什么结果、解决什么问题 | 指向某条迁移目标，不是复述章节内容 |
| **R**ole 角色 | 学生扮演什么身份 | 一个会真的使用该学科的身份（顾问、审稿人、工程师），不是"学生" |
| **A**udience 对象 | 成果交给谁看 | 明确且通常是非专业对象——迫使学生解释而非套公式 |
| **S**ituation 情境 | 在什么场景下 | **必须是教材没直接教过的场景**（与迁移目标的情境要求同一条标准） |
| **P**roduct 成果 | 产出什么 | 可评的具体产物（方案、报告、可运行代码、审阅意见），不是"回答问题" |
| **S**tandards 标准 | 什么样算做好了 | 直接展开为第 3 节的评价标准表 |

**好例**（承接 ubd-framework.md 2.4 节的迁移目标好例"在降维、压缩、推荐场景中主动识别低秩结构"）：

> **G**：为一个图片存储服务给出降维压缩方案，并论证画质与成本的取舍；
> **R**：该服务的技术顾问；
> **A**：不懂线性代数的产品经理；
> **S**：服务存储成本超支，手上有一批灰度图片，要在"画质可接受"与"存储省一半"之间做决定——教材讲过奇异值分解，但没讲过图片压缩这个应用；
> **P**：两页方案 + 一段可运行的验证代码（含压缩率与误差的实测数字）；
> **S**：见第 3 节评价标准表。

**坏例**："综合运用本书所学知识，写一篇关于矩阵分解应用的报告。" 六要素里只剩下一个模糊的成果——没有角色、没有对象、没有具体情境，学生只能靠猜；而且"综合运用所学"停留在教过的范围内，是应用不是迁移。

## 3. 评价标准（rubric）的写法

**结构**：维度 3–5 个 × 水平 3–4 级。维度太少评不出层次，太多作者自己也用不动。

**两条硬要求**：

1. **维度必须从持久理解与迁移目标推出**，不能用通用的"完整性 / 条理性 / 创新性"——那是作文评分表，评不出学科理解。至少有一个维度直接对准迁移（能否在新情境中识别学科结构），否则 rubric 退化成交付物检查清单；
2. **每格写可观察的表现描述**，不写程度副词。"较好地理解低秩结构"无法判定，两个人给分能差两级；"能指出图片矩阵的奇异值快速衰减，并据此判断可低秩近似"可以判定。

**示例**（承接第 2 节的任务，3 维度 × 3 水平；实际可用 4 级并扩到 5 个维度）：

| 维度 | 优秀 | 合格 | 未达成 |
| ------ | ------ | ------ | -------- |
| **结构识别**（迁移核心） | 自主把"压缩存储"重述为低秩近似问题，并说明图片矩阵为何具备低秩结构 | 在提示"能否用矩阵分解"后能正确建立联系 | 把任务当作套用某个公式，未识别出低秩结构 |
| **方法选择与论证** | 说明为何选奇异值分解、秩 k 依据什么定（如奇异值衰减曲线或误差阈值），并指出方法的失效场景 | 选对方法并给出 k 的一个合理依据，未讨论失效场景 | 未说明选择理由，或 k 的取值无依据 |
| **面向非专业对象的表达** | 不使用未解释的术语，用画质与成本的具体数字支撑取舍建议 | 表达基本可读，但残留少量未解释术语 | 直接罗列公式与代码，产品经理无法据此决策 |

注意三个维度都在评"学科理解的表现"，没有一格在评排版或字数。

## 4. 与例题习题计划、Bloom 梯度的分工

- **例题习题计划**评的是掌握程度（在教过的情境里能否正确执行），**表现性任务**评的是迁移（在没教过的情境里能否识别与运用）——两者是 UbD 阶段二的两类证据，不可互相替代，也不必互相重复；
- 表现性任务通常落在 Bloom 的评价/创造层。**在评价/创造属少量点缀的学科里**（`stem` 档案即如此，各学科的章内分布见所用档案第 3 节），它与"高层题常放在末章"是同一件事的两面。**任务不计入全书梯度矩阵的题目统计**（梯度报告的统计口径是三类题，见 bloom-levels.md 第 5 节），但作者若因梯度报告缺高层而补题，表现性任务是自然的落点。

## 5. 自查清单（随阶段 3 呈现前必过）

1. 每个任务六要素齐全，情境确实是教材没直接教过的？
2. 每条迁移目标至少被一个任务覆盖，且该任务附了评价标准表？
3. 每张表的维度 3–5 个、水平 3–4 级，且至少一个维度对准迁移？
4. 维度是否都从持久理解或迁移目标推出，没有混入"完整性/条理性"这类通用项？
5. 每格是可观察的表现描述，没有"较好地""基本能"这类无法判定的程度副词？

任何一项不过，先修再呈现——与五件套 gate 同一条纪律：gate 是给作者确认方向的，不是让作者替 skill 做质检的。
