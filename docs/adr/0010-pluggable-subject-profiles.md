# ADR 0010:学科差异收拢为可插拔的学科档案

## 状态

已接受。

## 背景

[ADR 0006](0006-verified-computation-for-exercises.md) 把学科边界锁在 STEM,理由是其例题"有标准解、可验证"。但"STEM 假设"并没有集中在一处,而是弥散在四个文件里:

- 题型分类与验证方式表([exercise-design.md](../../skills/textbook-exercises/references/exercise-design.md) 第 2 节);
- Bloom 动词表与六层判定标尺([bloom-levels.md](../../skills/textbook-outline/references/bloom-levels.md) 第 2、4 节);
- 四段标题文案与后三段的教学动作([chapter-template.md](../../skills/textbook-chapter/references/chapter-template.md));
- 数学公式规范的适用声明(writing-style.md 第 13 节被无条件适用)。

后果有两个:支持一个新学科门类要同时改四处;改完两套规则各自漂移,没有任何机制拦得住。这与 [ADR 0003](0003-single-authoritative-handoff-contract.md)「契约只在一处定义」的立身之本相悖——学科差异同样是一种契约,却没有单源。

还有一个运行时缺陷:作者坚持写文科时,只有 textbook-outline 知道要降级,textbook-chapter 与 textbook-exercises 并不知道,各自仍按 STEM 假设跑。

被否决的两个替代方案:

1. **在 exercise-design.md 里加文科分支**。该文件会从 99 行涨到 200+,两套验证纪律混住,生成文科题时读到"必须 Python 复算";而且只解决了题型一处,动词表、段式、文体三处仍要各自加分支。
2. **按学科门类 fork 子 skill**(如 `textbook-exercises-humanities`)。这是 copy-paste 扩展:每 fork 一次就复制一份三类题定位、Bloom 标注、编号规则、输出契约,内核规则从 1 处定义变成 N 处;再加语言学习、法学、艺术教育时同样要再 fork。且"文科"本身不是一个整体(语言学习与法学的答案高度可核查,史论与文学评论才是难点),二分法建模本身就是错的。

## 决策

先做可变点分析,得出真正随学科变化的只有四处——**题型集、验证手段、认知动词与层级示例、章内段义与载体扩展**;其余(五阶段调度、双 gate、状态机、UbD 五件套、章节树双向对齐、梯度三规则、GRASPS 与 rubric、Bloom 六层骨架与通用动词、三类题支撑纪律、四段式脚手架逻辑、阶段 5 六项走查)与学科无关。

据此把四个可变点收拢为**可插拔的学科档案**:

- 规格与索引在 [subject-profile-spec.md](../../skills/textbook/references/subject-profile-spec.md),档案在 `profiles/<id>.md`,固定四个小节,**每节恰有一个消费者**(阶段 1 / textbook-exercises / textbook-outline / textbook-chapter);
- 契约新增字段 `学科档案`:阶段 1 判定一次 → 落盘为 `.progress.json` 的 `subject_profile` → 逐章原样透传,中途不重判;
- **内核只写学科无关规则,档案只写本学科增量**。判断法:一段话换个学科照样成立,它属于内核,不得进档案;
- 红线的边界明确写死:档案定义"**用什么方式**验证",不定义"**是否需要**验证"。档案第 2 节题型表的「验证手段」列不允许为空,由 `validate_skills.py` 机械校验——绕不过来自结构,不靠指令里写"不许";
- 三类题的**类型名**(示范例题/引导练习/独立习题)留在内核不可改,档案只定义章内**段标题文案**——Bloom 回写、梯度统计、验证行清点全按类型名对账。

## 后果

支持一个新学科门类 = 加一个档案文件 + 索引登记一行 + 追加 evals 用例,**内核零改动**;改一份档案只影响用它的教材。原先"加一个学科改四处、且必然漂移"的问题消失,漂移改由第一层防线拦住。

代价是多了一层间接:段标题文案、验证手段从"写在模板里"变成"查档案第 N 节",阶段 5 走查与章内自查多一次查表。缓解办法是档案必须给出可直接复制的完整文案,不做模板化推导。

引入一种新的失败模式:**选错档案**。判定在阶段 1 单点发生,选错则全书歪。因此档案第 1 节强制写明与相邻档案的分界,阶段 1 产出必须含一行 `学科档案：<id>` 让作者过目,索引匹配不到时不得静默套用——必须说明将按哪份最接近的档案处理并指出已知差异,由作者决定。

对未来提案的约束:再有学科要支持,先问四个可变点够不够,不够就修订规格;**若发现必须改内核才能容纳,说明可变点划分不对,先讨论再动手,不得在内核里加学科分支**。任何新增档案都不得以"本学科没法验证"为由留空验证手段列——那等于借档案绕开 ADR 0006 的红线,校验脚本会直接拒绝。
